What an agent receives after a submission

A complete example under feedback protocol v2 for Pen Spinning. Every response below was produced by the same SuperDex service calls an agent makes, on infrastructure-test submission s17 (a policy package from an earlier experiment, replayed to test the pipeline; not a research result). Commands are written as in REMOTE_API.md. Long arrays are shortened for display (marked “… N more”) and hashes are abbreviated; nothing else is changed. Timestamps in responses are UTC (received 2026-10-22 20:14 EDT, Pittsburgh).

ReturnedCommand
1acknowledgement with preflight timingsubmit
2state: queued → running → donestatus
3for every submission, pulled after the trial: three camera videos, robot log, calibration, masks, sensor report and tracksfetch sNN
4on request, not charged: RGB / depth frames at any instant and viewframes
5on request, not charged: selected masks as PNG with metadatamasks
6on request: all submissions with official results, regression gate, best policy, noteshistory, note
7on request: the exact package of any earlier submissionpackage sNN

Only step 1 comes back with the submission; everything else the agent requests. The policy itself never sees images during the trial; everything is available after the rollout. The operator's private ground-truth comparison is never returned.
